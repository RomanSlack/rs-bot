# rs-bot status report

**2026-08-01** · 65 commits · 72 tests · **the robot stopped bolting to the servo case**

Previous: [2026-07-28](2026-07-28-status.md)

---

## What changed today

The two servos arrived, and with them a set of calipers. For eleven weeks the
model had nothing to be wrong against. Today it did, and it was.

Three things happened, in this order, and each one made the next one possible:

1. **The horn was measured** and the wheel's pocket turned out to be too small
   to accept it. A confirmed fault, caught before any money was spent on prints.
2. **The manufacturer's dimensioned drawing turned up** on the Amazon listing.
   The document this project spent weeks proving could not be recovered.
3. **The forty M2 screws that go into the servo case were deleted**, and four of
   the five servo mounts were redesigned to capture the case instead.

## 1. The bench, against the model

| | model | bench | |
|---|---|---|---|
| case length | 45.40 | **45.35** | 0.05 |
| case width | 24.80 | **24.77** | 0.03 |
| shaft tip to tip | 39.60 | **37.24** | **2.36** |
| horn outer diameter | 20.00 | **19.93** | fault, see below |
| horn plate | - | **2.51** | |
| horn overall, with nub | - | **4.50** | |
| horn screw, major dia | 3.00 | **2.93** | M3 confirmed |

Two dimensions agreeing to 0.05 and 0.03 mm is what made the third worth
believing. It ruled out both a bad caliper and a misread datum before anyone
had to argue about it.

**The Ø19.93 horn against a Ø20.00 pocket is the fault.** `cad/wheel.py` cut
0.035 mm of clearance per side, from a service quoting +/-0.3 mm, so most wheels
would not have accepted the horn at all. It had survived the sweep that opened
every other fit in the robot to 0.1-0.9 mm purely because the horn's outside
diameter was unknown at the time. The pocket is now **Ø20.60**, sized to clear
the horn and the servo's own seating boss, which were previously both the same
diameter as the pocket. Three parts, one diameter, nothing fitted.

**And the fault we were braced for does not exist.** The reseller drawing showed
4.5 / 3.6 / 2.5 in section and the fear was that 4.5 was the seating flange,
standing the horn proud of a 4.0 mm pocket. Measured: 2.51 is the plate, 4.50 is
the overall including a nub, and the nub faces the crown. The joint seats.

## 2. The drawing, which was public the whole time

It was on the product listing. It is the **12 V part**, so unlike
`vendor/refs/STS3215_03a.step` (from SO-ARM100, which runs the 7.4 V servo) it
is our variant.

What it gives, all dimensioned:

```
 45.23 x 24.73        length and width
 12.5                 shaft from the case centre        model exact
 3.4 + 29 + 4.1       spline, body, rear boss
 = 36.5               tip to tip, and it adds up exactly
 Ø6                   rear boss                         model exact
 25T                  spline                            model exact
 M3 x 6               the centre horn screw             absent from the CAD
 8 x PA2.0            case mounting holes               model listed four
 2 x PA3.0 x 5        rear face                         absent from the CAD
 5264 / 2.54 / 3P     connector                         check cad/wiring.py
```

**The shaft-axis span is 36.50, not 39.60.** The model is 3.1 mm too tall, which
is worse than the 2.36 the caliper suggested, and it is now the manufacturer
saying so. The `3.4 + 29 + 4.1` breakdown adds up exactly, so this is not a
bounding box being mistaken for a case dimension. It is the real stack.

> This is the second time in a week. Last Monday this project proved at length
> that the horn pattern could only ever be recovered by consensus between mating
> parts, then found the manufacturer's drawing of it on a shopping page. Today
> it did the same thing with the case.
>
> **Look for the document before proving it cannot exist.** Twice is a pattern.

## 3. And the drawing still refuses to say where the case holes are

It labels them `8-PA2.0` with a leader line and never dimensions them. All three
metal brackets in the box attach through the **horn**; not one touches the case.

So the manufacturer declined to publish the positions for exactly the reason
`cad/servo.py` predicted: nobody mates with those holes, so nobody was ever
forced to get them right. Three independent witnesses now agree - TheRobotStudio
cradles the servo, Feetech's own brackets ignore the holes, and Feetech's own
drawing declines to answer.

> **A dimension is recoverable only if somebody was forced to mate with it.**
> The rule held. It just did not help, because this time the answer it returned
> was "there is nothing there to recover".

## 4. So the robot stopped using them

The decision was not close, and the reason is worse than "unverified".

**Four parts each drilled a DIFFERENT invented pattern into the same servo:**

| part | pattern it used |
|---|---|
| `chassis.py` | `HIP_BOLTS_X = 17.0` |
| `thigh.py` | 5.0 mm in from each end of the case |
| `shin.py` | `SERVO_BOLTS = 40.0` spacing |
| `ankle.py` | `SERVO_CASE_DY = 10.2` |

At most one of those could have been right. It was never one unverified number,
it was four mutually inconsistent ones going into the same 55 g plastic housing.
Capture deletes the problem rather than fixing it four times.

A rim takes the servo's reaction couple in **bearing** across the full side
faces, instead of as a force couple through four self-tappers. It is also how
TheRobotStudio mount this exact servo.

### What each mount got, and why they all differ

- **chassis, hip.** A rim inboard of the side plate. It was already most of the
  way there and nobody had noticed: `HIP_NOTCH_X` is `SERVO_W/2 + 0.8`, so the
  lower shelf's notch already gripped the case over its 3 mm thickness, by
  accident of being sized to clear it.
- **thigh, knee.** A full rim, two sides and a lower end. The inboard plate had
  to grow from +/-10 to +/-15.3: it never even reached the sides of a servo
  24.8 mm across, which is why `cad.servo.cradle()` had nothing to attach to.
  Axial retention is free here, because the horn drives the shin and the servo
  is trapped between the cradle and its own output.
- **shin, ankle pitch.** Side walls only. A lower end wall would sit 50.6 mm
  from the roll axis, **inside** the annulus the wheel-drive servo sweeps
  between the two modes.
- **ankle yoke, roll.** Two walls, bottom open. Closing it into a channel is the
  better section and the floor forbids it: with the servo's real z range the
  bottom wall lands at -13.1, and in foot mode the floor is 12 mm below the
  axle. It would have printed 1.1 mm underground.

Two opposed walls react a couple on their own. The end walls were never the ones
carrying it.

**The fifth mount is deliberately not done.** The roll bracket's wheel-servo
bolts are removed, but no cradle replaces them yet: the arm's frame and
`envelope.WHEEL_SERVO`'s frame disagree about where that case sits, and guessing
would produce a fifth invented pattern. Pin the box first.

## 5. Four bugs fell out, all of them pre-existing

**Three sets of case screws cut nothing at all.**

| | what it did |
|---|---|
| shin, lower ankle bolt | missed the case end by 3.5 mm, and missed the standoff too |
| ankle yoke, 2 of 4 | fell below the ring, which only starts at z = 2 |
| roll bracket, both | ran *parallel* to the face they were meant to clamp |

`cad/fasteners.py` caught none of them, because it checks that a hole is
**parallel to its servo's shaft**, not that it **arrives at the servo**. All
three were ordered, counted and priced in the BOM. Removing them changes nothing
structurally, which is the finding: those joints have never been fastened.

The shin's comment even argued the case, at length and with numbers: "1.63 N.m
through bolts 12 mm apart is 136 N each, at 40 mm it is 41." Computed for a pair
that did not exist.

**`ROLL_SV` was 3.4 mm out of position**, and carried the superseded
35.4 x 24.7 x 45.2 guesses. The sim's own geom is 39.6 x 24.8 x 45.4. It
surfaced only because the cradle is the first feature ever positioned *from*
that constant rather than merely near it, and `assemble_check` promptly put
491 mm3 of new wall inside the servo. A box that is 3.4 mm wrong but never used
for anything is invisible.

**A fillet was eating the servo's seat.** Widening the shin's standoff gave
`soften()` new long edges, and the r = 1.0 blend where a cradle wall rises off
the seating face is **concave**, so it added 0.2 mm of material into the space
the servo has to sit in. 3.4 mm3, found by `assemble_check`. At the bench that
is a servo rocking on a fillet instead of seating on a face, which is the same
0.5 mm standoff fault this design has already been bitten by once, minus the
bolts that used to tighten it out. Fixed by cutting the pocket from the servo
box **after** the fillet, so the pocket is defined by the part it holds rather
than by whatever the blend leaves behind.

**And the cradles stood in a cable.** The ankle-servo lead runs down the shin
and into the roll servo, and it had never needed a channel because it crossed
open air. The new walls put 62 mm3 of yoke and 7 mm3 of shin through the middle
of it.

Worth recording how that surfaced, because it is the one thing today that
neither geometric check could have found:

> `fitcheck` and `assemble_check` were both **clean**. Neither of them models a
> cable, so neither of them can. What caught it was the wiring test, which
> asserts that the only blocked run left in this robot is the roll-to-wheel one,
> blocked by exactly the wheel envelope and nothing else.
>
> **A test written to pin a known limit is what noticed a new one.** That is the
> argument for pinning limits as tests rather than as comments.

Four more channels, two per part, because the yoke drops 28 mm in z between the
modes and a channel cut for one pose is the wrong channel half the time. Back to
0 of 8 runs blocked in wheel mode and 2 of 8 in foot mode, which is exactly
where it stood before any of this started.

## 6. Where the checks stand

```
fitcheck          0 interpenetrating pairs, both modes
                  1 connected group, both modes
                  0 collisions across the 26-pose flip
assemble_check    0 interfering pairs, both modes
                  16 seated faces, up from 12 - the cradles
wiring            wheel mode 0 of 8 runs blocked
                  foot mode 2 of 8, the roll-to-wheel run, by the wheel
fasteners         every servo screw still runs along its servo's axis
pytest            72 passed
```

The fastener order lost **40 x M2 x 10** and gained **10 x M3 x 6**, the centre
horn screw the drawing specifies and the CAD had never drawn.

Mass went **1875 g to 1904 g**. The cradles cost 29 g, which is what a rim round
five servos costs and is the price of not depending on holes nobody can locate.

## 7. A viewer, because the model needed checking rather than the part

`cad/servo_view.py`, at localhost:8782. Every other viewer in this project
renders a part so you can check the part; this one renders the **model** so you
can check it against the thing on the desk. The STEP solid, the horn built from
bench numbers, and both envelopes as wireframes, so the 2.36 mm is something you
can see rather than something you have to take on trust.

It also has an orthographic toggle, and that is not decoration. In perspective
the far end of a 45 mm case is drawn smaller than the near end, which is exactly
the error you do not want while deciding whether a model matches a caliper.

## Open, and deliberately so

- **`LENGTH`, `WIDTH` and `HEIGHT` still carry the STEP's values**, not the
  drawing's 45.23 / 24.73 / 36.50. They feed `chassis.py`, `thigh.py`, the axis
  check in `fasteners.py` and the port positions in `wiring.py`, so correcting
  them moves real geometry on four parts. It wants the FEA and the full suite
  re-run against that change **alone**, or it will be impossible to tell which
  change broke what. The numbers are recorded in `cad/servo.py` ready to use.
- **`solid()` still returns the wrong-variant STEP**, which is oversized along
  z. Every clearance check running against it is therefore conservative, which
  is the safe direction to be wrong in. Shrinking the envelope to the drawing
  while the solid stays big would quietly remove that margin.
- **The roll bracket's wheel servo has no cradle.**
- **The case hole positions are still unknown.** They no longer matter to this
  robot, which is the point, but the eight holes are real and a future design
  that wants them will have to measure them off the part.
- **Backlash is still unmeasured.** It needs 12 V and a TTL bus adapter, and
  there is no serial code in this repo at all. It remains the number the whole
  design sits closest to.

## The rule, and today it earned its keep three times

> A check that cannot fail is worse than no check at all, because it reads as
> evidence.

`fasteners.py` is that check. It has been reporting "every servo screw runs
along its servo's mounting axis" for a week, in green, while three of those
joints had screws that never touched a servo. It was not lying. It was
answering a narrower question than anybody read it as answering.

What did catch things was `assemble_check`, twice in one afternoon, and both
times because a number was finally **used** rather than merely stored. A
constant nobody builds from is not verified by anything.
